# Obsidian: второй мозг, который читает агент

> Раздатка занятия 6. Всё, что нужно, чтобы собрать у себя такую же базу знаний,
> какую вы видели на экране.

Пять занятий мы всё пишем в `.md`-файлы. Здесь ответ на вопрос «а куда это всё девается
потом»: зачем вообще база знаний, как она устроена у преподавателя и как довести свою до
рабочего состояния за один вечер.

---

## Зачем это в курсе про Claude Code

Три причины, по которым Obsidian стоит рядом с агентом, а не в стороне.

**1. Обычная папка с обычными файлами.** Obsidian не хранит заметки в своей базе.
Vault (хранилище) это папка на диске, а заметки в ней: файлы `.md`. Тот же формат,
в котором вы весь курс пишете `CLAUDE.md` и `SKILL.md`. Значит, Claude Code
работает с базой знаний ровно так же, как с проектом: открыл папку и читает, пишет,
ищет, связывает.

**2. Markdown переживёт любое приложение.** Evernote умирает, Notion однажды закроется,
Google Docs привязан к аккаунту. Файл `.md` откроется через двадцать лет в любом
текстовом редакторе. Плюс это формат, который LLM понимает однозначно: в отличие от
`.docx` и `.pdf`.

**3. Знания курса надо где-то держать.** За восемь занятий вы получаете десятки
находок: какой промпт сработал, где Claude ошибся, какой MCP подключили. Без базы
это уходит в историю чатов и теряется.

## Как это устроено у преподавателя

Живая база: **524 заметки**, ведётся с весны 2026 года.

```
AI second brain/          ← папка vault на диске
├── 00-Inbox/             ← входящие, необработанное
├── 01-Projects/          ← активные проекты с результатом и сроком
├── 02-Areas/             ← зоны ответственности (работа, тело, финансы, техника…)
├── 03-Resources/         ← справочники по интересам и темам
├── 04-Archive/           ← завершённое и неактуальное
├── Meetings/             ← транскрипции встреч
├── attachments/          ← картинки и файлы к заметкам
├── CLAUDE.md             ← инструкция для агента, работающего с базой
└── _VAULT_INDEX.md       ← автоматический индекс всех заметок
```

Разбор структуры и откуда она взялась: **[para-structure.md](para-structure.md)**.

Два факта, которые обычно удивляют:

- **Плагинов установлено два.** Не двадцать. Git (синхронизация) и Custom Frames
  (встроить веб-сервис в панель). Всё остальное: стандартные возможности Obsidian.
  Самая частая болезнь новичка: собрать «идеальный сетап» из тридцати плагинов по
  ютуб-туториалам и не написать ни одной заметки.
- **База синхронизируется через GitHub, а не через платный Obsidian Sync.**
  Плагин Git коммитит vault каждые 5 минут в приватный репозиторий. Бесплатно, история
  версий за всё время, и та же механика, которую вы уже освоили на занятии 2.

## Четыре паттерна работы

Именно так база наполняется в реальности. Ни один из них не про «сесть и красиво
всё разложить».

### 1. Кинуть ссылку: получить заметку

Самый частый сценарий. В чате Claude Code, открытом в папке vault:

```
https://www.youtube.com/watch?v=T6Mfl1OywM8

Сделай заметку в Obsidian.
```

Дальше агент работает сам: понимает, что это YouTube, вытягивает субтитры, переводит,
структурирует, выбирает папку, проставляет ссылки на связанные заметки и дописывает
строку в индекс. Через минуту в базе лежит оформленный конспект часового видео.

Работает потому, что за фразой «сделай заметку в Obsidian» стоит **скилл**: тот
самый механизм из занятия 4. Разбор и готовый пример, который можно поставить себе:
**[skill-example/](skill-example/SKILL.md)**.

### 2. Ссылки между заметками вместо папок

Внутри заметок связи ставятся двойными квадратными скобками: `[[Название заметки]]`.
Это вики-ссылка: кликаешь и проваливаешься.

Смысл: папка у заметки может быть только одна, а связей сколько угодно. Заметка про
MCP-сервер физически лежит в `03-Resources/AI`, но ссылается на проект в
`01-Projects`, на инструмент в `02-Areas/Техника` и на статью-первоисточник. Через
полгода вы попадёте в неё не через дерево папок, а по ссылке из соседней темы.

Обратная сторона тоже работает: в панели **Backlinks** видно все заметки, которые
ссылаются на текущую. Это и есть то, из чего вырастает граф.

### 3. `CLAUDE.md` в корне vault

Vault это проект, а у проекта есть инструкция для агента. В корне базы лежит
`CLAUDE.md`: где какая папка, на каком языке писать, как называть файлы, куда класть
что. Агент читает её автоматически и перестаёт задавать вопросы «а куда сохранить?».

Подробно, с примером готового файла: **[claude-code-in-vault.md](claude-code-in-vault.md)**.

### 4. Индекс вместо чтения всей базы

`_VAULT_INDEX.md`: одна строка на заметку: имя и теги. 524 заметки умещаются в
файл, который агент читает целиком за один раз. Без него, чтобы найти связанные
заметки, пришлось бы открывать пятьсот файлов: долго и дорого по токенам.

Индекс собирается скриптом внутри скилла, руками его не трогают.

## Что сделать у себя

Порядок именно такой, по нарастанию.

| Шаг | Что | Файл |
|---|---|---|
| 1 | Установить Obsidian, развернуть PARA-структуру, положить `CLAUDE.md` | [prompts/obsidian-para-setup.md](prompts/obsidian-para-setup.md) |
| 2 | Подключить приватный репозиторий и автосинхронизацию | [prompts/obsidian-github-sync.md](prompts/obsidian-github-sync.md) |
| 3 | Поставить скилл «сделай заметку» и проверить на живой ссылке | [skill-example/SKILL.md](skill-example/SKILL.md) |

Первые два шага делает агент: ваша задача запустить промпт и ответить на вопросы.
