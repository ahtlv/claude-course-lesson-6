# Синхронизация Obsidian с GitHub

> Бесплатная замена платному Obsidian Sync: база уезжает в приватный репозиторий,
> история версий сохраняется целиком, на другой машине разворачивается за минуту.

---

## Что за плагин

**Git** (в каталоге сообщества: просто `Git`, в файлах `obsidian-git`), автор
Vinzent03.

- Репозиторий: **https://github.com/Vinzent03/obsidian-git**
- Документация: **https://publish.obsidian.md/git-doc**
- Установка: Obsidian → `Настройки` → `Сторонние плагины` → `Обзор` → искать `Git`

Плагин не делает ничего волшебного: он вызывает обычный `git`, который у вас уже стоит
с занятия 1. Просто вам не нужно открывать терминал: коммит и пуш делаются по
расписанию и по команде из палитры.

**Важно:** на десктопе плагин использует системный Git. На iOS и Android поддержка
ограниченная и работает нестабильно: если синхронизация на телефоне критична,
честнее посмотреть в сторону платного Obsidian Sync.

## Сначала: правила безопасности

### Репозиторий обязан быть приватным

В базе знаний со временем оказывается всё: рабочие заметки, черновики, личное,
иногда ключи и пароли, которые вы «на минутку» скопировали. Публичный репозиторий с
vault это утечка, о которой вы узнаете последним.

Приватный по умолчанию, и никогда не переключать. Промпт из раздатки создаёт репозиторий
именно приватным.

### Токен в адресе репозитория: так не делать

В интернете полно инструкций вида «вставьте токен прямо в URL»:

```
❌ https://ghp_ВАШТОКЕН@github.com/username/vault.git
```

Так работает, но токен ложится открытым текстом в файл `.git/config` внутри vault и
светится в любом выводе `git remote -v`. Дальше он утекает в скриншот, в бэкап, в чат
с агентом.

Правильно: один раз научить сам Git ходить в GitHub через уже настроенный `gh`:

```bash
gh auth setup-git
```

После этого адрес репозитория остаётся чистым:

```
✅ https://github.com/username/vault.git
```

а пароль подставляется из системного хранилища (Keychain на macOS, Credential Manager
на Windows). У вас `gh` авторизован с занятия 1, так что команда отработает сразу.

### Что не должно уезжать в репозиторий

Файл `.gitignore` в корне vault:

```gitignore
# Obsidian
.obsidian/workspace.json

# macOS
.DS_Store
**/.DS_Store

# Крупные медиа
*.mp4
*.mp3
*.mov
*.wav

# Windows
Thumbs.db
```

Зачем каждая строка:

- **`workspace.json`**: какие вкладки у вас сейчас открыты. Меняется каждую минуту и
  на разных машинах разный. Без этой строки вы получите конфликт при каждой синхронизации.
- **`.DS_Store` / `Thumbs.db`**: служебный мусор macOS и Windows.
- **Медиа**: гигабайты видео в git-репозитории превратят каждый пуш в мучение. Крупные
  файлы держите вне vault или в облаке, а в заметке оставляйте ссылку.

## Настройки плагина

`Настройки` → `Git`. Значения, которые стоят у преподавателя:

| Настройка | Значение | Что делает |
|---|---|---|
| Vault backup interval (minutes) | `5` | Каждые 5 минут коммитит изменения локально |
| Auto push interval (minutes) | `0` | Автопуш выключен, отправка вручную |
| Pull updates on startup | ✅ | При запуске Obsidian подтягивает изменения |
| Pull before push | ✅ | Перед отправкой сначала забирает чужое |
| Sync method | `merge` | Как объединять расхождения |
| Commit message | `vault backup: {{date}}` | Текст коммита с подстановкой даты |

**Про автопуш.** Он выключен намеренно: коммиты копятся локально, а отправка
происходит по команде, когда вы закончили работать. Если у вас две машины и вы
переключаетесь между ними в течение дня: поставьте автопуш `10` минут, иначе на
второй машине не окажется свежих заметок.

## Две команды, которыми всё делается

Палитра команд: **`Cmd+P`** (macOS) или **`Ctrl+P`** (Windows/Linux). Начать набирать
`Git:`: появится список.

| Команда | Когда |
|---|---|
| `Git: Commit-and-sync` | Основная. Закоммитить всё, забрать чужое, отправить своё |
| `Git: Pull` | Сели за вторую машину: сначала это |

Остальные команды из списка на старте не нужны. Статус (сколько файлов изменено, какая
ветка) виден в строке состояния внизу окна Obsidian.

## Что делать при конфликте

Конфликт возникает, если одну заметку поменяли на двух машинах и ни одна не
синхронизировалась. Obsidian Git создаст файл `conflict-files-obsidian-git.md` со
списком проблемных заметок.

Не паникуйте и не удаляйте ничего руками. Откройте Claude Code в папке vault и
скажите прямым текстом:

```
В моём Obsidian vault git-конфликт. Покажи, какие файлы конфликтуют,
и помоги разрешить: сохрани обе версии текста, ничего не удаляй.
```

Профилактика простая: перед началом работы на второй машине: `Git: Pull`, в конце:
`Git: Commit-and-sync`.

## Развернуть базу на новой машине

Ради этого всё и затевалось. На чистом компьютере:

1. Установить Obsidian и Git.
2. Склонировать репозиторий в любую папку: `gh repo clone username/vault`.
3. В Obsidian → `Открыть папку как хранилище` → выбрать склонированную папку.
4. Плагин Git уже внутри (папка `.obsidian` тоже в репозитории): включить его в
   настройках сторонних плагинов.

Все заметки, структура, настройки и оформление: на месте.
