# Синхронизация базы знаний с GitHub

> Инструкция одинаковая для Windows, macOS и Linux: агент сам определяет систему.

**Когда:** сразу после [`obsidian-para-setup.md`](obsidian-para-setup.md), когда база развёрнута. Git и `gh` у вас уже стоят с
занятия 1, аккаунт GitHub тоже есть.
**Что делает:** превращает папку базы в git-репозиторий, создаёт для неё **приватный**
репозиторий на GitHub и делает первый пуш. Плагин Obsidian Git ставится вручную после
этого: за него агент взяться не может, это интерфейс приложения.
**Как использовать:** отправьте промпт как есть, из любой папки. Агент спросит путь к
базе, если не найдёт её сам.

> ⚠️ Репозиторий обязан быть **приватным**. В базе знаний со временем оказывается всё:
> рабочие черновики, личное, иногда ключи, которые вы «на минутку» скопировали.
> Публичный репозиторий с vault это утечка, о которой вы узнаете последним.
> Промпт создаёт приватный, но проверьте глазами.

```text
Помоги подключить мою базу знаний Obsidian к приватному репозиторию на GitHub,
чтобы она автоматически бэкапилась и синхронизировалась между устройствами.

Работай по полным путям, на каждом шаге показывай результат.

1. Определи мою операционную систему.

2. Найди папку моей базы знаний Obsidian. Признак: папка с подпапками 00-Inbox,
   01-Projects, 02-Areas, 03-Resources, 04-Archive и файлом CLAUDE.md внутри.
   Нашёл ровно одну: назови полный путь и продолжай. Нашёл несколько или не нашёл:
   ОСТАНОВИСЬ и спроси меня. Путь не выдумывай.

3. Проверь, что в корне базы есть .gitignore и в нём есть строка
   .obsidian/workspace.json
   Если файла нет, создай, если строки нет, допиши. Это критично: без неё каждая
   синхронизация будет давать конфликт, потому что workspace.json меняется постоянно.

4. Убедись, что git умеет авторизоваться в GitHub через уже настроенный gh.
   Выполни: gh auth status
   Если авторизации нет, остановись и скажи мне, я авторизуюсь сам.
   Затем выполни: gh auth setup-git
   Это научит git брать доступ из системного хранилища.

   ВАЖНО: ни при каких обстоятельствах не вставляй токен доступа в адрес репозитория
   (в remote URL). Такой токен ложится открытым текстом в файл .git/config и утекает
   в первый же скриншот. Адрес репозитория должен остаться чистым:
   https://github.com/ИМЯ/РЕПО.git

5. Инициализируй git в папке базы, если он ещё не инициализирован.
   Сделай первый коммит со всем содержимым.

6. Создай на GitHub ПРИВАТНЫЙ репозиторий и запушь туда базу. Имя предложи сам
   по имени папки, но покажи мне его перед созданием.
   Используй gh repo create с флагом приватности. Публичный не создавай ни в каком
   случае, даже если что-то пойдёт не так.

7. Проверь результат и покажи мне:
   - вывод git remote -v (в адресе НЕ должно быть никакого токена)
   - подтверждение, что репозиторий приватный
   - ссылку на репозиторий на GitHub

8. В конце напиши мне короткую инструкцию: какой плагин установить в Obsidian
   и какие настройки в нём выставить.
```

## Дальше руками: плагин в Obsidian

Агент сделал git-часть. Плагин ставится в самом Obsidian, это две минуты.

**1. Разрешить сторонние плагины.**
`Настройки` → `Сторонние плагины` → выключить `Ограниченный режим` (Restricted mode).

**2. Найти и установить.**
`Обзор` (Browse) → в поиске набрать `Git` → плагин от автора **Vinzent03** →
`Установить` → `Включить`.

Репозиторий плагина: https://github.com/Vinzent03/obsidian-git

**3. Настроить.** `Настройки` → `Git`:

| Настройка | Значение |
|---|---|
| Vault backup interval (minutes) | `5` |
| Auto push interval (minutes) | `0` (или `10`, если работаете с двух машин) |
| Pull updates on startup | ✅ включить |
| Pull before push | ✅ включить |
| Commit message | `vault backup: {{date}}` |

**4. Проверить.** Измените любую заметку, затем `Cmd+P` / `Ctrl+P` →
`Git: Commit-and-sync`. Внизу окна Obsidian мелькнёт статус, а на GitHub появится
новый коммит.

## Что запомнить из команд

Всего две, обе через палитру `Cmd+P` / `Ctrl+P`:

- `Git: Commit-and-sync`: закоммитить, забрать чужое, отправить своё. Основная.
- `Git: Pull`: сели за вторую машину, первым делом это.

Подробности, разбор настроек и что делать при конфликте: в
[github-sync.md](../github-sync.md).
