# obsidian-note: источник превращается в заметку

## Vault

Путь: `/ПОЛНЫЙ/ПУТЬ/К/ВАШЕМУ/VAULT`
Inbox: `/ПОЛНЫЙ/ПУТЬ/К/ВАШЕМУ/VAULT/00-Inbox`

⚠️ Замените оба пути на свои, прежде чем пользоваться скиллом.

---

## Шаг 1: понять, что за источник

| Что пришло | Тип |
|---|---|
| Ссылка на `github.com/...` | Репозиторий |
| Ссылка на `youtube.com/...` или `youtu.be/...` | Видео |
| Любая другая ссылка | Статья |
| Тема словами, без ссылки | Исследование |

---

## Шаг 2: собрать материал

**Статья или репозиторий.** Загрузить страницу через `WebFetch`. Для репозитория
дополнительно взять README по адресу
`https://raw.githubusercontent.com/{owner}/{repo}/main/README.md`.

**Видео.** Нужны субтитры, из описания хорошей заметки не выйдет:

```bash
yt-dlp --dump-json --write-auto-subs --sub-langs "ru,en" \
       --sub-format vtt --skip-download \
       -o "/tmp/yt_%(id)s.%(ext)s" "URL"
```

Затем прочитать `/tmp/yt_{id}.ru.vtt` (или `.en.vtt`), убрать тайминги и служебные
теги, оставить чистый текст.

Если `yt-dlp` не установлен, предложить пользователю установить
(`brew install yt-dlp` на macOS, `winget install yt-dlp` на Windows) и подождать
подтверждения. Не устанавливать молча.

**Тема без ссылки.** Три-четыре поисковых запроса с разных сторон через `WebSearch`,
затем `WebFetch` двух-трёх самых толковых результатов.

## Шаг 3: написать заметку

Структура, одинаковая для всех типов источника:

```markdown
---
tags: [<тип>, <тема>]
date: ГГГГ-ММ-ДД
source: <ссылка>
author: <автор, если есть>
---

# <Название>

> <Одно предложение: о чём это и зачем читать>

---

## Главные идеи

<Основное содержание, структурированно, без воды>

## Конкретика

<Цифры, факты, названия инструментов, команды>

## Что с этим делать

<Как применить. Если непонятно как, честно написать, что пока непонятно>

[[Связанная заметка 1]] · [[Связанная заметка 2]]
```

Правила текста:

- **Всё на русском.** Исключения: названия инструментов (Claude Code, GitHub, Obsidian),
  общепринятые аббревиатуры (API, MCP, SEO), фрагменты кода.
- **Не копировать источник кусками.** Пересказывать своими словами, сжимать.
- **Заголовки информативные,** не кликбейтные.
- Таблицы вместо длинных списков, где это уместно.

## Шаг 4: проставить связи

Найти в vault заметки, к которым новая имеет отношение, и сослаться на них через
`[[Название заметки]]`.

Как искать: посмотреть имена файлов в `03-Resources/` и `01-Projects/`, найти
совпадения по теме и по упомянутым инструментам. Ссылка ставится **по точному имени
файла без расширения**: иначе Obsidian покажет её как несуществующую.

Две-три осмысленные связи лучше, чем восемь случайных.

---

## Шаг 5: выбрать папку и имя

| Тип заметки | Папка |
|---|---|
| Инструмент, технология, AI | `03-Resources/AI/` |
| Материал по рабочей теме | `03-Resources/<тема>/` |
| Относится к активному проекту | `01-Projects/<проект>/` |
| Не очевидно куда | `00-Inbox/` |

Имя файла: описательное, по которому заметку можно найти через поиск по названию:
`Название темы или инструмента.md`. Не `Статья 3.md`, не `Заметка от 5 августа.md`.
