# Хук: звук, когда агент закончил работу

> Инструкция одинаковая для Windows, macOS и Linux: агент сам определяет систему и
> подбирает команду.

**Когда:** на занятии 6, в блоке хуков. Ставим всей группой одновременно.
**Что делает:** дописывает в твой `settings.json` автоматику: когда Claude Code
заканчивает работу и возвращает тебе управление, компьютер издаёт короткий системный звук.
Отправил задачу → ушёл за кофе → вернулся на звук.
**Как использовать:** отправь промпт ниже как есть. Агент сначала **проверит звук вживую**
на твоей машине и спросит, слышал ли ты его, отвечай честно «да» или «нет», от этого
зависит, какая команда попадёт в конфиг.

> ✅ **Что считается успехом.** Главное здесь: не звук, а то, что **автоматика записана в
> `settings.json` и видна в `/hooks`**. Это работает одинаково на любой системе. Звук:
> приятный бонус: если у тебя он не завёлся, а `/hooks` показывает активный хук, значит всё
> сделано правильно, доиграем звук дома.

```text
Хочу настроить хук, который проигрывает короткий системный звук каждый раз, когда ты
заканчиваешь работу и возвращаешь мне управление.

Работай по полным (абсолютным) путям и на каждом шаге показывай, что получилось.

1. Определи мою операционную систему.

2. Найди мой settings.json. Сначала посмотри, есть ли видимая папка конфига claude-config
   рядом с моими проектами (мы выносили её на занятии 3): если есть, работай с файлом
   внутри неё, а не с тем, что лежит в системной папке: там, скорее всего, символическая
   ссылка на этот же файл, и править надо оригинал.
   Если папки claude-config нет, работай с системным файлом:
   ~/.claude/settings.json на macOS/Linux, %USERPROFILE%\.claude\settings.json на Windows.
   Если файла нет вообще, создай его с содержимым {} и скажи мне об этом.

3. ПОДБЕРИ РАБОЧУЮ КОМАНДУ ЗВУКА и обязательно проверь её вживую, до того как что-либо
   записывать в конфиг. Запусти команду в терминале и спроси меня, услышал ли я звук.
   Если я говорю «нет», переходи к следующему варианту из списка для моей системы и
   спроси снова. В конфиг запиши только тот вариант, на который я ответил «да».

   macOS, по порядку:
     1) afplay /System/Library/Sounds/Glass.aiff
     2) afplay /System/Library/Sounds/Ping.aiff
     3) osascript -e beep

   Windows, по порядку (важен именно такой порядок: первый вариант проверен на реальной
   Windows и работает, остальные два нужны только если у меня выключены системные звуки):
     1) rundll32 user32.dll,MessageBeep
     2) powershell -c "[System.Media.SystemSounds]::Asterisk.Play(); Start-Sleep -Milliseconds 500"
     3) powershell -ExecutionPolicy Bypass -c "[System.Media.SystemSounds]::Asterisk.Play(); Start-Sleep -Milliseconds 500"

   Linux, по порядку:
     1) paplay /usr/share/sounds/freedesktop/stereo/complete.oga
     2) aplay /usr/share/sounds/alsa/Front_Center.wav
     3) printf '\a'

   Если ни один вариант не дал звука, не выдумывай свои и не ставь ничего лишнего.
   Возьми первый вариант из списка для моей системы, запиши его и честно скажи мне:
   хук настроен, но звук на этой машине не воспроизводится, разберёмся отдельно.

4. Прочитай settings.json целиком и запомни его текущее содержимое. Ты будешь ДОПИСЫВАТЬ
   в него блок hooks, ничего не затирая: ни model, ни permissions, ни что-либо ещё, что
   там уже есть. Если блок hooks уже существует, добавляй в него, а не заменяй его.

5. Добавь хук на событие Stop. Структура ровно такая (matcher для Stop не нужен):

   "hooks": {
     "Stop": [
       {
         "hooks": [
           {
             "type": "command",
             "command": "СЮДА_ПРОВЕРЕННУЮ_КОМАНДУ",
             "async": true
           }
         ]
       }
     ]
   }

   Два поля объясни мне словами, зачем они:
   - "async": true, чтобы звук не задерживал возврат управления;
   - на macOS/Linux добавь в конец команды 2>/dev/null || true, чтобы возможная ошибка
     звука не выглядела как сбой.

6. Проверь, что получившийся файл: валидный JSON. Это критично: битый settings.json молча
   отключает ВСЕ настройки из него, и выглядит это как «сломался Claude Code». Если после
   правки файл невалиден, верни исходное содержимое и скажи мне.

7. Покажи мне итог:
   - полный путь к файлу, который ты изменил;
   - только блок hooks из него, а не файл целиком;
   - подтверждение, что остальные настройки на месте.

8. В конце напомни мне: чтобы хук заработал, надо перезапустить окно VS Code, а проверить
   его командой /hooks прямо в диалоге.
```

**Дальше на занятии**: перезапусти окно VS Code, набери `/hooks` и найди в списке своё
событие `Stop`. Дай агенту любую мелкую задачу и дождись, пока он закончит.

> ⚠️ **Событие `Stop` срабатывает не только «когда всё готово».** Оно срабатывает на каждой
> остановке агента, в том числе после `/clear`, при возобновлении сессии и при
> автоматическом сжатии контекста. Если звук раздался в неожиданный момент это не поломка,
> а нормальное поведение.

## Если звука нет

Сначала ответь себе на вопрос: **хук виден в `/hooks`?** Если да, автоматика настроена
правильно, дело только в звуке, и занятие для тебя засчитано.

<details>
<summary><b>🪟 Windows</b></summary>

Проверь команды руками, прямо в `cmd`: по одной, слушая после каждой:

```cmd
rundll32 user32.dll,MessageBeep
```

```cmd
powershell -c "[System.Media.SystemSounds]::Asterisk.Play(); Start-Sleep -Milliseconds 500"
```

Первая не использует PowerShell вообще и **проверена на реальной Windows перед занятием:
она звучит**. Поэтому если не звучит именно она, дело почти наверняка в системных звуках, а
не в Claude Code. Проверь: Параметры → Система → Звук, и убедись, что системные звуки не
выключены и громкость не на нуле.

⚠️ **`Start-Sleep` в конце: не украшение.** Метод `.Play()` асинхронный: без задержки
PowerShell успевает завершиться раньше, чем звук прозвучит, и хук «работает» молча.

⚠️ Если увидишь ошибку вида «невозможно загрузить файл … выполнение сценариев отключено»,
это про политику запуска **файлов сценариев** (`.ps1`). Наши команды идут через `-c`, то
есть под ограничение попадать не должны. Если всё же попали, используй третий вариант, с
`-ExecutionPolicy Bypass`: он действует только на этот один запуск и ничего в системе не
меняет.

🚫 **Не прописывай `"shell": "powershell"` в настройках.** Это поле запускает `pwsh`
(PowerShell 7), которого на обычной Windows нет: хук просто не выполнится.

</details>

<details>
<summary><b>🍎 macOS</b></summary>

```bash
afplay /System/Library/Sounds/Glass.aiff
```

Не звучит, посмотри, какие звуки вообще есть в системе, и подставь любой существующий:

```bash
ls /System/Library/Sounds/
```

</details>

<details>
<summary><b>🐧 Linux</b></summary>

```bash
paplay /usr/share/sounds/freedesktop/stereo/complete.oga
```

Пути к звукам сильно зависят от дистрибутива и окружения рабочего стола. Если файла нет,
поищи, что есть:

```bash
ls /usr/share/sounds/
```

Совсем на крайний случай подойдёт системный «бип» терминала: `printf '\a'`, но он работает
не во всех эмуляторах терминала.

</details>
