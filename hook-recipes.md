# Рецепты хуков

Звуковой хук стоит. Здесь ещё четыре, каждый ставится одним промптом, тем же способом. Бери
один, тот, что закрывает твою боль, и поживи с ним неделю.

Как и со звуком, агент сам определяет систему (Windows, macOS, Linux), находит твой
`settings.json` в `claude-config`, **дописывает** блок `hooks`, ничего не затирая, и проверяет,
что файл остался валидным JSON. После установки перезапусти окно VS Code и проверь хук
командой `/hooks`.

| Хук | Событие | Что даёт |
|---|---|---|
| [Агент ждёт тебя](#1-агент-ждёт-тебя) | `Notification` | Звук или всплывашка, когда агент остановился и просит разрешения |
| [Журнал команд](#2-журнал-команд-агента) | `PreToolUse` | Файл, где видно, какие команды агент запускал и когда |
| [Автокоммит](#3-автокоммит-после-каждого-ответа) | `Stop` | Точка возврата после каждой задачи, без «я забыл закоммитить» |
| [Проверка HTML](#4-проверка-html-после-правки) | `PostToolUse` | Агент сам видит незакрытый тег сразу после правки |

## 1. Агент ждёт тебя

**Боль:** отправил задачу, ушёл, вернулся через двадцать минут, а агент всё это время стоял и
ждал твоего «разрешить». Звуковой хук на `Stop` тут не поможет: агент не закончил, он ждёт.

```text
Поставь мне хук на событие Notification: когда ты останавливаешься и ждёшь моего
разрешения или ответа, компьютер должен подать знак.

1. Определи мою систему.
2. Найди мой settings.json: сначала в видимой папке claude-config, если её нет, то в
   системной папке .claude. Прочитай его целиком.
3. Подбери команду, которая показывает системное уведомление с текстом «Claude ждёт тебя».
   Если на моей системе уведомление без установки дополнительных программ не получается,
   возьми короткий системный звук, отличный от звука на Stop. Проверь команду вживую и
   спроси меня, увидел или услышал ли я. В конфиг запиши только проверенный вариант.
   На Windows не используй PowerShell-скрипты из файлов.
4. Допиши хук в блок hooks, ничего не затирая. "async": true.
5. Проверь, что settings.json валидный JSON. Покажи мне только блок hooks.
6. Напомни перезапустить окно VS Code и проверить командой /hooks.
```

## 2. Журнал команд агента

**Боль:** что-то сломалось, и непонятно, что агент делал три задачи назад.

```text
Поставь мне хук, который записывает в журнал каждую команду терминала, которую ты
запускаешь: дата, время и сама команда, одна строка на команду.

1. Определи мою систему и найди settings.json (видимая папка claude-config, иначе системная
   папка .claude).
2. Событие PreToolUse, matcher "Bash". Хук только записывает и всегда разрешает действие,
   ничего не блокирует.
3. Журнал пиши в файл claude-commands.log в папке claude-config (или в системной .claude).
   Если для этого нужен маленький скрипт, положи его в claude-config/hooks/ и напиши так,
   чтобы он работал на моей системе без установки новых программ. Если нужна программа,
   которой у меня нет (например jq), скажи об этом и предложи вариант без неё.
4. Проверь вживую: запусти любую безобидную команду и покажи мне последнюю строку журнала.
5. Добавь claude-commands.log в .gitignore папки claude-config: журнал не должен уезжать
   на GitHub.
6. Проверь, что settings.json валидный JSON, покажи только блок hooks. Напомни
   перезапустить окно VS Code.
```

## 3. Автокоммит после каждого ответа

**Боль:** агент сделал три задачи подряд, а коммит один, и откатить одну задачу не получится.

> ⚠️ **Ставь в проект, а не глобально.** Этот хук коммитит всё в той папке, где работает
> агент. Глобально он начнёт коммитить и там, где ты этого не ждёшь. Поэтому промпт пишет хук
> в `.claude/settings.json` конкретного проекта.

```text
Поставь в этот проект (не в глобальный конфиг) хук на событие Stop: когда ты заканчиваешь
ответ и в проекте есть незакоммиченные изменения, сделай коммит.

1. Определи мою систему. Работай с файлом .claude/settings.json в корне текущего проекта,
   создай его, если нет.
2. Хук: добавить все изменения и закоммитить с сообщением «авто: правки Claude». Если
   изменений нет, ничего не делать. Не пушить: пушу я сам, когда проверю.
3. Если нужен скрипт, положи его в .claude/hooks/ проекта и сделай так, чтобы он работал
   на моей системе без установки новых программ.
4. Проверь вживую: поменяй один пробел в README, закончи ответ и покажи мне git log
   последних двух коммитов.
5. Проверь, что settings.json валидный JSON, покажи блок hooks. Напомни перезапустить окно
   VS Code.
```

Не понравилось? Попроси агента: «убери хук автокоммита из этого проекта».

## 4. Проверка HTML после правки

**Боль:** агент поправил страницу, «готово», а в браузере пол-страницы съехало из-за
незакрытого тега.

```text
Поставь мне хук на событие PostToolUse с matcher "Write|Edit": после каждой правки
файла .html проверяй, что теги закрыты и разметка не сломана. Если нашлась ошибка,
хук должен вернуть её текст тебе, чтобы ты сразу починил. Другие файлы не проверять.

1. Определи мою систему и найди settings.json (видимая папка claude-config, иначе системная
   папка .claude).
2. Подбери способ проверки, который работает у меня без установки новых программ. Node.js
   у меня должен стоять с занятия 3 (Playwright), Python может быть: проверь, что есть, и
   выбери. Скрипт, если нужен, положи в claude-config/hooks/.
3. Хук ничего не блокирует, только сообщает. Вывод короткий: файл, строка, что не так.
   Не больше десяти строк, чтобы не забивать мне контекст.
4. Проверь вживую: сделай во временной копии страницы незакрытый тег, покажи, что хук
   его поймал, и удали копию.
5. Проверь, что settings.json валидный JSON, покажи только блок hooks. Напомни
   перезапустить окно VS Code.
```

## Если что-то пошло не так

- **Claude Code ведёт себя странно после установки хука** → «Проверь мой settings.json на
  валидность и покажи блок hooks». Битый JSON молча отключает все настройки из файла.
- **Хук мешает** → «Убери хук [название] из settings.json, остальное не трогай».
- **Хук не срабатывает** → `/hooks`: если его там нет, окно VS Code не перезапущено или хук
  записан не в тот файл.

Полная документация по хукам: https://code.claude.com/docs/en/hooks
